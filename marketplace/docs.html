Publica una extensión en AxiomCode

La marketplace acepta extensiones alojadas en repositorios públicos de GitHub. No necesitas subir ZIP: AxiomCode inspecciona el repositorio, fija la publicación a un commit concreto y genera el paquete instalable.

Inicio rápido

  1. Crea un repositorio público en GitHub.La marketplace no puede publicar repositorios privados.
  2. Añade extension.json en la raíz.Los campos mínimos son id, name y version.
  3. Sube los archivos de tu extensión.El repositorio completo se usa como paquete, con las exclusiones indicadas abajo.
  4. Pega la URL del repositorio en Publicar.Ejemplo: https://github.com/usuario/mi-extension.
  5. Analiza y publica.Render valida el repositorio y registra la extensión en Supabase.

Estructura recomendada

extension.json debe estar directamente en la raíz del repositorio.

mi-extension/
├─ extension.json
├─ icon.png
├─ main.js
├─ README.md
└─ assets/
   └─ ...
Importante: las carpetas .github/ y node_modules/, además de .gitignore, no se incluyen en el paquete publicado.

extension.json

Este es un manifiesto válido para publicar en la marketplace:

{
  "id": "tuusuario.mi-extension",
  "name": "Mi extensión",
  "version": "1.0.0",
  "description": "Descripción corta de la extensión.",
  "publisher": "TuNombre",
  "keywords": ["productividad", "editor"],
  "icon": "icon.png",
  "contributes": {
    "commands": [
      {
        "command": "mi-extension.hello",
        "title": "Decir hola"
      }
    ]
  }
}
CampoRequeridoUso
idSíIdentificador único. Usa letras, números, punto, guion o guion bajo.
nameSíNombre visible. Máximo 120 caracteres.
versionSíVersión publicada. Recomendado: SemVer, por ejemplo 1.2.0.
descriptionNoDescripción visible en la marketplace.
publisherNoAutor o equipo. Si falta, se usa el propietario del repo.
keywordsNoHasta 20 etiquetas para búsqueda y descubrimiento.
iconNoRuta relativa a un icono que exista dentro del repositorio.
contributesNoContribuciones que AxiomCode puede interpretar, como comandos.

Reglas y límites

  • El repositorio debe ser público y estar en GitHub.
  • extension.json debe existir en la raíz.
  • Sin límite propio de cantidad de archivos impuesto por AxiomCode.
  • Máximo 100 MiB por archivo Git normal, porque GitHub bloquea objetos mayores.
  • Sin límite total propio de tamaño impuesto por AxiomCode. GitHub recomienda mantener el tamaño en disco de .git dentro de 10 GB para rendimiento y aplica un máximo de 2 GiB por push.
  • El ID debe coincidir con ^[A-Za-z0-9][A-Za-z0-9._-]{1,127}$.
  • Una vez que un ID se publica desde un repositorio, otro repositorio no puede apropiarse de ese mismo ID.
  • Los IDs reservados por AxiomCode no pueden ser usados por extensiones de la comunidad.
  • La versión de una actualización debe ser mayor que la ya publicada.

AxiomGuard · seguridad de extensiones

Toda extensión de comunidad se analiza antes de publicarse y vuelve a analizarse en el equipo del usuario antes de instalarse. El análisis local es obligatorio; VirusTotal puede aportar reputación adicional cuando el servidor tiene una API key configurada.

  • Bloquea ejecución directa de procesos del sistema mediante child_process y bypasses equivalentes.
  • Bloquea PowerShell ofuscado, loaders remotos, mecanismos de persistencia y patrones de evasión de antivirus.
  • Detecta patrones asociados a robo de credenciales, wallets, minería de criptomonedas y exfiltración.
  • Bloquea binarios y scripts del sistema como .exe, .dll, .msi, .ps1, .bat, .cmd, .vbs, .hta, .jar, .node y .sh dentro de extensiones normales.
  • Calcula SHA-256 de los archivos inspeccionados y conserva el estado de seguridad de la instalación.
  • Las extensiones copiadas manualmente a la carpeta local también son analizadas; una extensión bloqueada no se activa.
  • Las extensiones JavaScript locales de Scratch Power Mode pasan por AxiomGuard antes de ejecutarse.
Importante: ningún análisis estático o antivirus garantiza detectar el 100% del malware. AxiomGuard usa varias capas para reducir el riesgo y aplica bloqueo preventivo cuando encuentra indicadores críticos.

Qué ocurre al publicar

  1. Inspección.Render consulta GitHub, valida el manifiesto y ejecuta AxiomGuard sobre el código publicable.
  2. Commit congelado.La publicación queda asociada al SHA del commit actual, para que el paquete no cambie silenciosamente.
  3. Validación del paquete.Se respetan los límites que GitHub aplica al repositorio y se rechazan árboles truncados por la API de GitHub.
  4. Registro.La extensión se guarda en Supabase y aparece en /api/catalog.
  5. Instalación.AxiomCode descarga los archivos por HTTPS, valida ID/versión y ejecuta AxiomGuard de nuevo antes de activar la extensión.

Actualizar una extensión

Para publicar una nueva versión, usa el mismo repositorio y conserva el mismo id.

  1. Modifica tu extensión.
  2. Aumenta version, por ejemplo de 1.0.0 a 1.1.0.
  3. Haz commit y push a GitHub.
  4. Vuelve a pegar la misma URL en la sección Publicar.

Cuando AxiomCode detecte una versión mayor, mostrará la opción Actualizar a los usuarios que tengan la extensión instalada.

Errores comunes

“extension.json requiere id, name y version”

Falta uno de los tres campos obligatorios o el archivo no contiene JSON válido.

“Ese ID ya pertenece a otro repositorio”

Ese identificador ya fue publicado desde otra URL de GitHub. Usa el repositorio original o un ID diferente.

“Publica una versión mayor que…”

Incrementa el valor de version antes de volver a publicar.

“GitHub no permite objetos Git normales mayores de 100 MiB”

Ese archivo supera el límite aplicado por GitHub para un objeto Git normal. Reduce su tamaño o usa un mecanismo de distribución apropiado para archivos grandes.

“El repositorio debe ser público”

Cambia la visibilidad del repositorio a pública antes de enviarlo a la marketplace.

“AxiomGuard bloqueó la extensión”

El análisis encontró un indicador crítico, un tipo de archivo ejecutable no permitido o una combinación de comportamientos de alto riesgo. Elimina ese comportamiento y vuelve a analizar el repositorio.
